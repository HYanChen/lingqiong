# 灵穹知识库与飞书式知识工作台能力对齐审计

审计日期：2026-07-12  
审计对象：灵穹原生知识工作台 `/knowledge`  
参考范围：飞书知识库、文档块编辑、多维表格的桌面信息架构与常用操作  
结论口径：功能与操作参考，不复制飞书商标、代码、视觉资产或私有实现

## 1. 结论摘要

灵穹已经完成从“BookStack 跳转入口”到原生知识工作台的核心重塑，并形成以下真实闭环：

```text
知识空间
  -> Wiki 页面树
     -> 块文档 -> 自动保存 -> 评论 -> 历史版本 -> 恢复
  -> 多维表格
     -> 字段/记录 -> 六类视图 -> 详情协作 -> 附件
     -> CSV 导入导出 -> 自动化执行 -> 运行日志
```

当前界面已对齐飞书式浅灰白桌面布局和主要操作层级；数据、权限、评论、历史、自动化与附件均由真实后端承载。它可以作为灵穹内部团队的首发生产版本，但与成熟企业协作套件相比，实时多人协同、细粒度权限、复杂字段计算、外部分享和合规治理仍需继续建设。

## 2. 对齐分级

本文使用三种状态：

- **已实现**：前后端均有真实数据或操作闭环。
- **核心已实现**：常用流程可用，但飞书的企业级或高级形态尚未覆盖。
- **后续建设**：当前未达到可对外承诺的企业级能力。

## 4. 多维表格能力对照

### 4.1 信息架构

已对齐的四层操作结构：

1. 约 184px 的数据表/仪表盘/工作流导航。
2. 数据表标题栏与分享、自动化、通知、更多、搜索和新增。
3. 数据表下方的视图标签。
4. 添加记录、字段配置、视图配置、筛选、分组、排序、行高与数据区。

这套结构与飞书多维表格的当前桌面工作方式相近，但视觉保持灵穹蓝灰色系，没有使用飞书名称或图形标识。

### 4.3 字段能力

后端与前端类型系统已经覆盖 23 种字段：

`text`、`number`、`select`、`multi_select`、`date`、`checkbox`、`url`、`person`、`attachment`、`phone`、`email`、`location`、`barcode`、`progress`、`currency`、`rating`、`autonumber`、`button`、`lookup`、`relation`、`formula`、`created_time`、`updated_time`。

审计判断：

- 文本、数字、选择、日期、复选、链接、电话、邮箱、货币、进度和评分等基础输入已进入真实记录保存链路。
- 附件通过记录附件接口独立管理，不伪装为普通文本字段。
- 自动编号、公式、查找引用、创建时间、更新时间在界面中按只读值展示。
- “已声明字段类型”不等于“已具备飞书同等级计算能力”。公式求值、关联反向关系、Lookup 实时重算、跨表汇总仍属于后续建设。

## 5. 协作与数据操作审计

### 5.1 真实接口映射

| 用户操作 | 接口组 | 数据副作用 |
| --- | --- | --- |
| 搜索页面/表格/记录 | `GET /_wcu-api/knowledge/search` | 无，结果按权限过滤 |
| 管理空间成员 | `/spaces/:spaceId/members` | 新增、修改角色、删除成员 |
| 编辑文档 | `/spaces/:spaceId/pages/:pageId` | 更新内容与 revision，生成版本历史 |
| 页面评论 | `/pages/:pageId/comments` | 评论创建、解决/重开、软删除 |
| 查看/恢复历史 | `/pages/:pageId/versions` | 首次读取确保初始版本；恢复写新页面版本 |
| 编辑记录 | `/tables/:tableId/records` | 记录创建、更新、删除和活动写入 |
| 记录评论 | `/records/:recordId/comments` | 评论与评论活动写入 |
| 记录活动 | `/records/:recordId/activity` | 只读活动流 |
| 附件 | `/records/:recordId/attachments` | 文件与元数据创建/下载/删除 |
| 视图配置 | `/tables/:tableId/views` | 筛选、排序、分组、行高、字段显隐持久化 |
| CSV | `/tables/:tableId/import`、`/export` | 批量写入或下载当前视图数据 |
| 自动化 | `/tables/:tableId/automations` | 规则、运行记录与执行结果持久化 |

### 5.2 真实性与失败处理

- 所有可变资源使用 revision 乐观锁；过期版本返回 409。
- 前端成功提示只在接口成功后显示。
- 自动化手动运行不是“只创建 queued 记录”：前端会继续调用 `/runs/:runId/execute`，执行成功后才提示完成。
- CSV 导入正确处理 `createdFields[]` 和 `failed[]`，不会把数组误显示为数量。
- 附件上传使用 multipart，限制单文件 20MB；下载不经过浏览器本地伪造。
- 评论删除为服务端软删除，历史版本恢复为服务端写操作。
- 甘特与表单均是实际视图类型；表单提交调用真实记录创建接口。
- API 错误统一显示在工作台提示条，不静默吞掉写入失败。

## 6. 权限与安全对齐

### 已实现

- 前端只请求 `/_wcu-api/knowledge`，数据库只由 `platform-api` 访问。
- owner/editor/commenter/viewer 四级空间角色。
- 前端根据实时 `accessRole` 隐藏或只读化编辑、删除、自动化和成员管理操作，不再让只读成员反复触发 403。
- 读取、评论、写入和成员管理分别在服务端校验。
- Admin 复用 `projects.read` / `projects.write`。
- 全局搜索在服务端按用户可访问空间过滤。
- OIDC/平台会话继续作为统一身份来源。
- 上传文件名清理、大小限制、安全下载头和路径隔离。
- 删除与恢复均要求明确确认，后端再次校验 revision。
- 页面和多维表格删除先进入真实回收站；恢复需要 write，永久删除需要 manage。

### 仍需企业级能力

- 页面/子树继承权限、记录行级和字段级权限。
- 外链分享的密码、到期、水印、下载限制和访问审计。
- 组织架构、用户组、部门和批量授权。
- 附件病毒扫描、内容安全审核、对象存储与生命周期。
- 管理员可导出的不可篡改审计日志与合规保留策略。

### 7.3 正式服务器复验边界

本地生产镜像和真实 API 已通过上述回归，但这不等于远程宝塔环境已经上线。正式服务器仍需使用正式域名、TLS、MySQL 数据和反向代理执行同一套验收，并检查备份与回滚能力。

正式执行示例：

```bash
KNOWLEDGE_TEST_BASE_URL=https://正式域名 \
KNOWLEDGE_TEST_ADMIN_USERNAME='正式管理员账号' \
KNOWLEDGE_TEST_ADMIN_PASSWORD='正式管理员密码' \
pnpm audit:knowledge
```

正式服务器还应复验：

- 1440px 桌面、1024px 窄桌面和移动端布局。
- Enter、Shift+Enter、Backspace、`/` 命令和自动保存状态。
- owner/editor/commenter/viewer 四角色的可见按钮与实际 403 行为一致。
- 甘特日期比例、表单提交、记录四页签和搜索直达；本地桌面环境已通过，正式域名需复验。
- 长标题、中文/英文混排、空空间、空表格、200 条以上记录和 20MB 边界附件。

## 8. 企业级差距优先级

### P0：对外企业客户前必须补齐

1. 自动化独立异步 Worker、定时调度、重试、死信和执行告警；当前记录事件与手动运行已经可以真实执行。
2. 页面/记录/字段细粒度权限及组织架构同步。
3. 多人实时协同与离线冲突合并。
4. 附件对象存储、病毒扫描、备份恢复一致性。
5. 不可篡改审计日志、数据保留与删除策略。

### P1：显著影响飞书式完整体验

1. 块级评论、线程回复 UI、@成员和订阅。
2. 历史版本 Diff、命名版本和保留策略。
3. 公式、关联、Lookup、汇总和跨表计算引擎。
4. 甘特依赖/里程碑/关键路径；日历拖拽；看板拖拽改组。
5. 公共表单、条件字段、审批和提交防滥用。
6. 自定义仪表盘、透视表和跨表统计。

### P2：规模化与生态能力

1. XLSX、完整空间包、批量 API 和跨租户迁移。
2. Webhook、邮件、企业 IM、审批和第三方连接器。
3. 专用全文检索、中文分词、搜索建议和分析。
4. 富媒体块、文件预览、画板/流程图/思维导图嵌入。
5. 模板市场、空间分析、知识治理和内容生命周期。

## 9. 上线判定

知识工作台可以在以下条件全部满足后标记为首发上线：

- 新 Docker 镜像构建成功。
- `audit:knowledge` 全部通过且测试数据清理成功。
- 浏览器无阻断错误，关键布局完成视觉复核。
- 四类成员角色完成权限验收。
- MySQL 与附件目录完成上线前备份和恢复演练。
- 宝塔 HTTPS、上传大小和反向代理超时与当前配置一致。

在 P0 企业能力完成前，产品定位应为“灵穹团队原生知识与制作数据工作台”，不应宣传为飞书全部企业能力的等价替代品。
